# ts-pf rules

Rationale for each lock: [`DECISIONS.md`](../DECISIONS.md).

Contract-first TypeScript RPC library (`@ts-pf/*`). oRPC-like DX is the bar; oRPC's surface area is not. One procedure model. Every wire is an adapter. Do not grow the core into a dual-protocol platform.

## Packages

```
@ts-pf/contract          @ts-pf/protocol
     |     \               / |  |  \
     |      \             /  |  |   \
     v       v           v   v  v    v
 @ts-pf/server  @ts-pf/client  @ts-pf/http  @ts-pf/message
     |              |            /   \         /      \
     v              v           v     v       v        v
 @ts-pf/server-http  @ts-pf/client-http      message-server
                                            message-client

@ts-pf/file     → http + protocol
@ts-pf/stream   → http + protocol + contract
@ts-pf/sse      → stream + http + protocol

@ts-pf/message-server → message + server + protocol
@ts-pf/message-client → message + client + protocol

@ts-pf/docs     → contract + protocol + http
@ts-pf/openapi  → docs
@ts-pf/codegen  → docs
@ts-pf/swr      → contract (peer swr)
@ts-pf/mvc-kit  → contract (peer mvc-kit >= 4.9.0)
@ts-pf/astro/server → server-http + server + contract (type-only; peer astro >= 7.0.0)
@ts-pf/astro        → client-http + client + contract (type-only; `.` / `./client`; peer astro >= 7.0.0)
@ts-pf/mcp          → contract + docs + server + protocol (`./meta` no deps; `./sdk` peer @modelcontextprotocol/server >=2.3.0 <3)
```

- `contract` and `protocol` are siblings. Neither depends on the other.
- `server` and `client` each depend on both. They do **not** depend on `@ts-pf/http`.
- **Client never depends on server. Server never depends on client.**
- `server-http` never depends on `client-http`. `client-http` never depends on `server-http` (prod).
- `@ts-pf/http` is wire helpers only (codec, header, URL path, `httpStatus`, content-type / body-source helpers for wrapping codecs). No `FetchHandler`. No `FetchLink`.
- `@ts-pf/file` depends on `http` + `protocol`. `@ts-pf/stream` depends on `http` + `protocol` + `contract` (`stream()` schema). `@ts-pf/sse` depends on `stream` + `http` + `protocol`. All three are opt-in; default handler/link stay JSON.
- `@ts-pf/message` depends on `protocol` only. `@ts-pf/message-server` depends on `message` + `server` + `protocol` (never client, prod or dev). `@ts-pf/message-client` depends on `message` + `client` + `protocol` (never server in prod; one-way `message-server` **devDependency** for e2e).
- `@ts-pf/docs` depends on `contract`, `protocol`, and `http` (header name, `joinProcedurePath` for href, `PROTOCOL_HTTP_STATUS` for `protocolErrors`). Not imported by core.
- `@ts-pf/openapi` depends on `docs`. `@ts-pf/codegen` depends on `docs`. `@ts-pf/swr` depends on `contract` only (peer `swr`). `@ts-pf/mvc-kit` depends on `contract` only (peer `mvc-kit >= 4.9.0`).
- `@ts-pf/astro` `./server` depends on `server-http`, `server`, and `contract` (type-only, for `ContractClient`). `.` and `./client` depend on `client-http`, `client`, and `contract` (type-only). The server entry never imports the client entry. The client entry never imports the server entry. Peer `astro >= 7.0.0`. Root export is client-only.
- `@ts-pf/mcp` depends on `contract`, `docs` (`toJsonSchema`, `getDocs`, `walkContract`), `server` (`runProcedure`, `lookupProcedure`, `createLocalClient`, `isImplementedProcedure`, `validationError`), and `protocol` (`toWireError`, `PFError`, `isPFError`, `isUnexpectedError`, `defined`); from `contract` it uses `validateSchema` and `isContractProcedure`. `./meta` imports nothing (contract files import only it). `./sdk` adds the optional peer `@modelcontextprotocol/server >=2.3.0 <3`. Never `client`, `client-http`, or `server-http` in prod (tests may, as **devDependencies**, to bind a `createClient` proxy over a `FetchLink` to a `FetchHandler`); never `message-*` or `@modelcontextprotocol/sdk` (v1). The `./sdk` floor is tested by the `mcp-sdk-floor` CI job; the mcp package and example dev ranges start at it (`^2.3.0`) so one hoisted SDK copy serves both.
- Routers are nested objects, not a package.

| `mcp` | `mcp()` (`./meta`, no deps; `const` type parameter keeps `effect` literal); `createToolkit` (contract-mirroring builders; root members `$context` / `$tool` / `$host` / `$toolset` / `$coverage`; a contract key starting with `$` at any depth is a type error naming the key), `all`, `bindTools`, `audit`, `McpTools` / `McpCallInfo` / `McpToolDefinition` / `McpToolResult` (root; plus type-only exports of the inferred builder / toolset types so consumers can export toolsets under `declaration: true`); `createMcpFactory` (`./sdk`: a fresh `McpServer` per request with passthrough schemas; from an `app` or bound `McpTools`). | `message` | JSON text frames + `MessageSession` / `Duplex` + port/ws/stdio duplex adapters + `createPushQueue` / `PushQueue` (the one push-to-`AsyncIterable` queue, one-shot `end()` / `fail()`, bounded by `PushQueueOptions` `{ highWaterMark, onPause, onResume }` with `push(value, size)`; message-server input and message-client output use it, no local copies) + the shared backpressure primitives: `BackpressureOptions` / `StallInfo` (the one option object both bindings take), `resolveBackpressure` (defaults 1 MiB / 30 s / `console.warn` on `aborted` only; `TypeError` naming the option) and `DrainWaiter` (the per-call drain wait; `onStall('paused')` once, `onStall('aborted')` on timeout; resolves before it notifies and swallows `onStall` throws; a second concurrent `wait` throws) — both exported `@internal` for the two bindings, not listed as consumer API. `MessageSession` keeps pending drain resolvers in a `Set` flushed by `enterClosed` (never a `.then` on a long-lived close promise per send). `Duplex.send` is `void \| Promise<void>` (a promise = above the write mark; must settle on close; rejection closes) and `Duplex` has optional `pause` / `resume`. `WebSocketLike.close(code?, reason?)` (browser `WebSocket` and npm `ws` both fit). | `message-server` | `DuplexHandler` (the multiplexer: `bind(duplex, { context })` over any `@ts-pf/message` `Duplex`), `PortHandler`, `WsHandler`, `StdioHandler` (`./stdio` only) — the three build their duplex and delegate to `DuplexHandler`. Calls `lookupProcedure` + `runProcedure`. `HandlerOptions` may include `interceptors`, `validation`, and `backpressure` (on by default; validated in the constructor). Output streams: `emitStream` awaits `SendResult.drained` between items, so the generator parks at its `yield`; after `drainTimeout` that call is aborted (signal, `iterator.return()` once, frames dropped, terminal `INTERNAL` / `Peer did not drain within <n> ms` via `sendResultErr` if the socket accepts it, `onStall('aborted')`, **not** `onError`) and the connection stays open. A call cancelled before its handler resolves closes the stream the handler then returns (`return()` once, through the same close path). Input streams: the `in-item` queue is bounded by `highWaterMark` (frame text length) and the connection pauses reads via `duplex.pause?.()` while any queue is over it. Handlers infer `TCtx` from `app` like `FetchHandler`; `bind(..., { context })` is typed with it. A `PFError` thrown by the context factory is the `hello-error` (its code reaches the client) and, like a handler's `PFError`, skips `onError`; other throws go to `onError` and send `INTERNAL`. `WsHandler.bind` returns `{ close(code?, reason?) }`: it closes the socket with that code (default `1000`) and reason **before** tearing down the session, so the session's own `1000` cannot win; `PortHandler` / `StdioHandler` / `DuplexHandler` handles keep `close()`. ts-pf sends only WebSocket close codes `1000` / `1002`; `PROTOCOL.md` reserves 4900–4999 and recommends 4400–4499 for apps. `attachRouter` / `ServerCall` stay internal; `BackpressureOptions` / `StallInfo` are type re-exports. |
| `message-client` | `DuplexLink` (the multiplexer: `Link` over any `@ts-pf/message` `Duplex`), `PortLink`, `WsLink`, `StdioLink` (`./stdio` only) — the three build their duplex and delegate to `DuplexLink`. Implements `Link`. `LinkOptions.backpressure` is the same object as the server's (on by default; validated in the constructor, `WsLink` included). Input pump: `pumpInput` awaits `SendResult.drained` between `in-item`s; after `drainTimeout` the call fails with `localFailure('Peer did not drain within <n> ms')`, `cancel` is sent if the socket accepts it, and the input iterator's `return()` runs once. Output queues are bounded by `highWaterMark` and pause reads via `duplex.pause?.()`. Uses protocol `isPFError` / `localFailure` / `isAsyncIterable` directly (no duck-typed `PFError` check, no local predicate copy). `ClientCall` stays internal; `BackpressureOptions` / `StallInfo` are type re-exports. |

## v1 locks

- Contract-first only. No server-first builder whose output is inferred from the handler.
- One procedure model. Pipes are adapters. Fetch is not privileged inside `@ts-pf/server` or `@ts-pf/client`.
- Spec: `packages/protocol/PROTOCOL.md`. Envelope is `{ input }`, `{ ok: true, output }`, `{ ok: false, error: { code, message, data? } }`. Optional `multipart/form-data` (`@ts-pf/file`), `application/jsonl` (`@ts-pf/stream`), `text/event-stream` (`@ts-pf/sse`) wrap the same envelopes over HTTP. Optional message transports wrap the same envelopes over WebSocket, stdio, and MessagePort.
- Versioning: one wire major, `PROTOCOL_MAJOR = 1` in `@ts-pf/protocol` (`x-ts-pf-protocol: 1` over HTTP, `v: 1` on message `hello` / `hello-ok`; `PROTOCOL_VERSION` is its string). `PROTOCOL.md` revisions (1.1, 1.2, …; the current one is in its title) are additive and keep the major: a receiver never rejects a value that 1.0 defined as valid, and a 1.x sender emits a new key / frame / header / content type only on opt-in. `FetchHandler` and the message server reject another major with `BAD_REQUEST` `Unsupported protocol version`; `FetchLink` rejects it with `INTERNAL` + HTTP status + `Unsupported protocol version (x-ts-pf-protocol: <value>)` (not local — the response came from a server); the message client fails locally with `Invalid response` (no `hello-ok` was accepted). Bump the major only when the JSON envelope, a required frame field, or the handshake changes.
- Server runtime: `runProcedure` / `lookupProcedure`. `FetchHandler` is Fetch `Request` / `Response` only, in `@ts-pf/server-http`. Message adapters live in `@ts-pf/message-server`.
- `.output()` is optional (`unknown` if omitted). `.input()` once; no stacked merge/pipe.
- `.use()` runs **before** input validation (`input: unknown`) and takes the same loose `MiddlewareFn<TCtx, unknown, unknown>` on `impl.use()` and on a per-procedure `.use()`, so an `impl.middleware()` result fits both. `.useAfter()` runs **after** (typed input when the input check ran) and is typed per procedure. Input checks default on. `validation.input: false` skips them, including stream input items, and `.useAfter()` then sees the raw value (and so does the handler, whose `input` type still says parsed). A handler that validates itself throws `validationError(toValidationIssues(issues))`. Middleware `next()` is single-call (documented, not enforced): the execution's `input` / `ctx` are shared by the chain, so any second call re-runs inner middleware on them and inherits inner middleware context (a second `.use()` call also re-validates the parsed input). Retries / hedging are a `CallInterceptor` (its `next()` gets a fresh execution).
- `$context<C>()` is the only source of context types. `impl.router()` brands the tree with it (`ImplementedRouter<T, TCtx>`, leaves `ImplementedProcedure<TContract, TCtx>`); `FetchHandler`, the message handlers, `createLocalClient`, and `@ts-pf/astro` infer `TCtx` from the brand and type `context` with it. Trees not produced by `impl.router()` infer `unknown` (only the router-level brand is read); use `impl.router()`, or pick procedures into a second `impl.router()` call, to keep the check. Middleware still does not infer added keys.
- Client-side input validation is off by default.
- Output checks, including stream output items, default off. `validation.output: true` runs them. Unary output schema failure is `INTERNAL` with no `issues` (input failure stays `VALIDATION`). A bad stream output item stays `VALIDATION` with `issues`. Invalid declared error `data` is always `INTERNAL` (not behind the output flag). HTTP status for those codes is mapped by `httpStatus()` in `@ts-pf/http` (500 / 422), not stamped by `runProcedure`. Parsed output (strip, defaults, transforms) is applied only when output checks run.
- Discriminator is JSON `error.code`. HTTP status is transport-only; never put `status`, `cause`, or `local` in the envelope.
- `PFError.status?: number` is optional transport metadata, not identity, and has **no default**. It is set only where a transport really has one: `FetchLink` stamps the HTTP response status on unary failures; `createErrorFactory` stamps a declared `ErrorDef.status` (and nothing when the definition omits it), and `runProcedure` fills it on a `PFError` thrown from middleware or the handler (not from a `CallInterceptor`) whose code is declared and whose `status` is unset, keeping `cause` (status only, never `message`); `errorFromEnvelope` (message transports) and mid-stream JSONL / SSE failures leave it `undefined`. Codec `BAD_REQUEST` throws and the `FetchHandler` stream-codec `BAD_REQUEST` carry an explicit `status: 400` that the protocol table overrides on HTTP anyway; message-server's own `BAD_REQUEST` / `NOT_FOUND` throws carry `status: 400` / `404` that never reach a frame. A `hello-error` carries no status on either side (`errorFromEnvelope`), even when the server's context factory threw a `PFError` with one. `httpStatus()` in `@ts-pf/http` is the only runtime place the HTTP default (400) lives: protocol codes → `PROTOCOL_HTTP_STATUS`, else `error.status ?? 400` (`@ts-pf/openapi` mirrors the same default when documenting declared errors). `ErrorDef.status` is optional HTTP / OpenAPI metadata.
- Local failures: `localFailure()` → `INTERNAL` with `local: true` and `status: 0`. `isLocalFailure` is `local === true`, never `status === 0`. That status is not on the wire and is not a protocol status. Abort message is `Request aborted`.
- Keep `ProtocolErrorCode` duplicated as a private union in `packages/contract/src/infer.ts`. Do not import `@ts-pf/protocol` from contract.
- Published `@ts-pf/contract` and `@ts-pf/docs` types must not import optional peer `typebox` (`check:exports` fails if a packed `.d.ts` does). Infer TypeBox schemas by walking `~kind` (`packages/contract/src/typebox-static.ts`). The runtime adapter still dynamic-imports `typebox/value` only when a TypeBox schema is validated. Do not re-add `import type { Static } from 'typebox'` to close an inference gap; extend the walk and its parity test.
- `METHOD_NOT_ALLOWED` stays in the closed set; only FetchHandler emits it. `PAYLOAD_TOO_LARGE` is shared (HTTP body cap + message outbound oversize).

**Not in core:** OpenAPI runtime / REST / Scalar, error-catalog RPC, Node `IncomingMessage` adapters, framework adapters, TanStack Query, lazy routers, `mergeRouters` / `compose()`, Map/Set on the wire, EventSource clients, Last-Event-ID, EventPublisher, non-TypeScript runtimes, clients, or generator templates (other languages get `PROTOCOL.md`, `conformance/`, `openapi()` `profile: 'codegen'`, and `docs/other-languages.md`). Feature slices nest `router({ planet: planetContract })` and `impl.router({ planet: planetApp })`. Each server exports one contract; clients import that contract only. File/Blob is `@ts-pf/file`. Message streams are `@ts-pf/stream`. SSE output framing is `@ts-pf/sse`. Procedure catalogs are `@ts-pf/docs`. OpenAPI 3.1 documents are `@ts-pf/openapi`. Typed-client `.d.ts` codegen is `@ts-pf/codegen`. Message transports are `@ts-pf/message` / `message-server` / `message-client`. SWR is `@ts-pf/swr`. mvc-kit Resource helpers are `@ts-pf/mvc-kit`. Astro endpoints and page callers are `@ts-pf/astro`. MCP tools are `@ts-pf/mcp`. Fetch is `@ts-pf/server-http` / `@ts-pf/client-http`. Do not add `.docs()` to the contract builder. None of these are core defaults. Do not redeclare `VALIDATION`, `INTERNAL`, `BAD_REQUEST`, `METHOD_NOT_ALLOWED`, or `PAYLOAD_TOO_LARGE` on `.errors()`.

`RpcCodec` declares stream capability with optional `streams` (read once by `FetchHandler`); encode returns `{ contentType, body }` (`string | Blob | FormData | ReadableStream<Uint8Array> | null`). Decode takes `RpcBodySource` (`contentType`, `text()`, `formData()`, `body()`). `JSONCodec` still emits `application/json` and the JSON envelope. `MultipartCodec`, `StreamCodec`, and `SseCodec` wrap it without changing contracts.

`CallOptions` is `{ signal?: AbortSignal }` on `ProcedureClient`. Do not add an oRPC-style ClientContext bag. `createClient` / `createLocalClient` forward it; `FetchLink` sets `RequestInit.signal`; `FetchHandler` passes `request.signal` into `runProcedure` → `HandlerFn` only (not middleware). Typed `ProcedureBuilder.handler` opts include `signal?: AbortSignal` — optional on purpose: `FetchHandler` and message handlers always pass one, `createLocalClient` without `{ signal }` / direct `runProcedure` / `@ts-pf/mcp` may not, and supplying one per call failed the bench gate (DECISIONS "Handler `signal` stays optional"). Fetch/interceptor catch: rethrow an existing `PFError`; abort/network → `localFailure(...)`. Before decode: an `x-ts-pf-protocol` response header that is present and not `PROTOCOL_VERSION` → `INTERNAL` + HTTP status + `Unsupported protocol version (x-ts-pf-protocol: <value>)` + `cause` = the `Response`, body unread, not `local` (`isLocalFailure` is false; `RetryPlugin` does not retry it by default). `decodeResponse` catch: rethrow a codec `PFError` only when `x-ts-pf-protocol` is present (and therefore matches); no protocol header → `INTERNAL` + HTTP status + `Non-RPC response (HTTP …)` + `cause` (`isLocalFailure` is false). Fetch interceptors see raw fetch throws / `Response`s, not mapped `PFError`; `isLocalFailure` is after the call. Client call interceptors wrap `Link.call` (`path` / `input` / `signal`; `next` may replace `input`/`signal`, not `path`). Server call interceptors wrap `runProcedure` (`procedure` / `path` / `input` / `context` / `signal`; `next` may replace `input`/`context`/`signal`; `context` replaces, does not merge). A server interceptor may call `next()` more than once, concurrently; `runProcedure` keeps `input` / `context` / `signal` per execution (each `next()` gets a fresh `Execution` object that the module-level step functions take as a parameter), never at `runProcedure` scope or in shared closure variables. Fetch `Interceptor`s still must not use `isLocalFailure`. `RetryPlugin` may; it is a call interceptor.

## Anti-patterns

- Do not invent `TransportHandler`. `FetchHandler` stays Fetch-only. `PortHandler.bind(port)` stays a different shape. `DuplexHandler` / `DuplexLink` are not that: they are generic only over `@ts-pf/message` `Duplex` *inside* the message family (same frames, same handshake), never a request shape shared with Fetch. A new pipe is a `Duplex` plus those two, not a copy of the multiplexer.
- Do not port `HandlerPlugin` onto WS / stdio / MessagePort.
- Do not reuse `RpcCodec` as a message framer. Reuse envelope types only.
- Do not put `.ws()` / `.stdio()` / `.port()` on procedures.
- Do not fold SSE into `@ts-pf/server-http`. Do not fold WebSocket into `@ts-pf/server-http`.
- Do not put `FetchHandler` back in `@ts-pf/server` or `FetchLink` back in `@ts-pf/client`.
- Do not put `JSONCodec` / `RpcCodec` back in `@ts-pf/protocol`.
- Do not depend on the `ws` npm package. Inject a `WebSocket` constructor. An `@types/ws` devDependency used only as a type fixture in `*.test-d.ts` (that npm `ws` sockets fit `WebSocketLike` / `WsLink` with no cast) is allowed; no runtime `ws` import.
- `@ts-pf/message-server` never depends on `@ts-pf/client` (prod or dev).
- `@ts-pf/message-client` never depends on `@ts-pf/server` (prod).
- Do not import `@ts-pf/message-server` from `@ts-pf/server`; do not import `@ts-pf/message-client` from `@ts-pf/client` (prod).
- Do not `await runProcedure` inside `MessageSession` (`onFrame` must return without awaiting it).
- Context factory is `onHello`, not `onFrame`.
- Do not rewrite oversize payloads in `session.send`.
- Backpressure is the duplex's signal, never a frame: no `credit` / ack frames in wire major 1 (A8-A is v2). `Duplex.send` returns a promise only above the write mark; `session.send` stays synchronous and returns that promise as `SendResult.drained`, which must settle on close. Only frames with a successor on the same id await it (`item`, `in-item`); `result` / `done` / `cancel` / `hello*` never do. Do not `await` a sync send (`drained` absent) — the unary path and `onHello` stay zero-await. A drain timeout is a stall, not a handler failure: `onStall`, not `onError`; `INTERNAL` with the fixed `Peer did not drain within <n> ms` message, not a new code. Protection is on by default; `highWaterMark: Infinity` is the only spelling of "unbounded". Do not add a second option bag or per-transport knobs: one `BackpressureOptions` on `HandlerOptions` and `LinkOptions`.
- Do not make a receiver drop or reject frames to bound memory; it pauses the duplex (`pause?.()`) where the pipe can, and documents that `MessagePort` and non-`ws` server sockets cannot (npm `ws` 8.x can).
- `onStall` is observability only: it runs after the outcome is decided, its throws are swallowed, and the default logs `aborted` only (never `paused`, which is normal flow control). Do not route a stall through `onError`.
- Do not re-export `createPortDuplex` / `createWsDuplex` / `createStdioDuplex` from `@ts-pf/message-server` or `@ts-pf/message-client`.
- Do not add a published Node HTTP upgrade helper or `child_process.spawn` adapter; user owns listen/upgrade/spawn/Worker bootstrap.
- Do not serve REST or OpenAPI from `FetchHandler`. `openapi()` never emits GET/PUT/path params; a userland GET bridge adds its `get` operations to the returned document. Scalar/Swagger stay userland.
- `FetchHandler` and `FetchLink` stay POST-only; cacheable GET reads are the userland bridge in `examples/plugins` (`GetBridgePlugin` + `getInterceptor`). The contract meta key `http` (`{ method?: 'GET' | 'POST'; cacheControl?: string }`) is reserved for it and for the deferred first-party binding (DECISIONS "Cacheable GET reads"); do not give `http` another shape.
- Do not serve `catalog.json` from `FetchHandler`. No `createClientFromCatalog` in v1.
- Do not reconstruct HTTP status from `error.code` on message transports.
- `@ts-pf/astro/server` is not imported by client islands. `@ts-pf/astro/client` does not import `@ts-pf/server`.
- Do not serve MCP through `FetchHandler` or a message handler (MCP is JSON-RPC 2.0; the SDK v2 owns the transport). Do not build on `@modelcontextprotocol/sdk` v1 or the deprecated low-level `Server`. Do not share one `McpServer` across requests. Contract files import `@ts-pf/mcp/meta` only. No `.rename()` (the toolset key is the name), no automatic switch to hosts by tool count, no resources / prompts in v1.
